# Backend - Recruiter Bot & SQL Detective

A candidate-matching API built with FastAPI and raw SQLite.

## Setup & Execution
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python -m app.seed
uvicorn app.main:app --reload
```

Interactive API documentation is automatically generated by FastAPI's Swagger UI and available at `http://127.0.0.1:8000/docs` (with an alternative ReDoc view at `/redoc`). To run tests, execute `pytest tests/`.
To view the SQL Detective solutions, reference `sql_detective/sql_detective.sql`.

## Architecture & Algorithm Trade-offs
- **Raw SQL over ORM**: The database layer uses Python's built-in `sqlite3` module with hand-written DDL and parameterized queries for a lightweight, zero-dependency database setup, strictly adhering to the no-ORM constraint.
- **Matching Algorithm**: Matches are computed dynamically rather than persisted in the DB, preventing stale data. The algorithm heavily favors exact skill overlaps (60% weight). Experience accounts for 30% (scored proportionally if below the minimum). Culture traits provide a 10% bonus.
- **Availability Penalty**: Candidates marked as "Not looking" or "2 weeks" are multiplied by 0.60 and 0.90 respectively. This ensures passive candidates are still discoverable, but actively searching candidates rank higher.

## AI Tool Usage
I utilized AI to format the raw fictional candidate data into a seed JSON file and quickly scaffold the FastAPI route boilerplate. I manually wrote the normalized schema DDL, the SQL Detective queries (accounting for traps like duplicate emails and LEFT JOIN logic), and the exact matching algorithm weights.
